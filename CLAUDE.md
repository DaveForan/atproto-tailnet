# atproto-tailnet

Tailscale-as-a-service where users authenticate with their AT Protocol (Bluesky) identity, receive isolated tailnets, and invite others by handle.

## Architecture

- **Service API**: TypeScript / Express 5 / Drizzle ORM / PostgreSQL
- **Dashboard**: React 19 / esbuild / lazy-loaded tabs / typed service layer (one module per API domain)
- **Control plane**: Rust coordinator (default) or one Headscale Docker container per tenant (legacy)
- **Coordinator**: Rust workspace at `coordinator/` — purpose-built mesh coordinator replacing Headscale. 10 crates (adds coord-netmap and coord-derp, the DERP relay + STUN): coord-core (types/traits including federation Link/Session/DID types, DEFAULT_IPV4/IPV6_PREFIX constants), coord-noise (Noise IK handshake via `snow`, transport via direct `chacha20poly1305` with Tailscale-compatible BE nonces, poison-recovering Mutex), coord-proto (Tailscale control protocol messages), coord-acl (PolicyEngine with per-tenant rules → Tailscale FilterRule), coord-store (MemoryStore with broadcast events + PgStore with sqlx + SqliteStore with sqlx-sqlite, shared generate_random_id + PEER_EVENT_CHANNEL_CAPACITY), coord-api (axum + hyper H2, admin auth middleware + federation message routes), coord-federation (14 modules: protocol, session, route_engine, abuse, scoping, handshake, auth, transport, discovery, store, broker, inbound, federation_store_memory, pg_store, sqlite_store — 5,800+ lines, 94 unit tests), coord-server (binary with broker tick loop, TOML config + env vars, uses create_pool). Protocol: JSON over HTTP/2 over Noise IK (`Noise_IK_25519_ChaChaPoly_BLAKE2s`). Key endpoints: `GET /key` (JSON mkey format), `POST /ts2021` (upgrade → Noise → H2), `POST /machine/register` (pre-auth key, node key rotation via OldNodeKey), `POST /machine/map` (streaming long-poll with zstd framing, delta PeersChanged/PeersRemoved, 60s keepalives, disco key propagation, HomeDERP field). Admin: `POST /api/preauth-keys`, `GET /api/nodes`, `POST /api/acl`, `POST/GET /api/tenants`, `GET/DELETE /api/tenants/{id}`, `GET /api/tenants/{id}/routes`, `GET/PUT /api/tenants/{id}/identity` (tailnet name → netmap `Domain`, owner id → `{login_name, display_name}` → per-owner Tailscale users/profiles, stable FNV user ids, placeholders when unknown; in-memory, pushed by TS `orchestrator/coordinator-identity.ts` at key issuance, coordinator resync and every 5th monitor tick), `GET/PUT /api/tenants/{id}/derp` (per-tenant DERP override via `DerpRegistry` in coord-netmap: custom regions 900-999 plus optional operator default map; in-memory, TS service is the source of truth) — constant-time Bearer token auth when COORD_ADMIN_KEY set. Federation: `POST /api/federation/messages/{hello,commit,keepalive,revoke,link-request,link-accept,link-reject,link-revoke}` — CFP-Recipient header for collective DID routing, InboundHandler with a pre-verification global rate limit (1200/min), per-DID RateLimiter (60 req/min, after signature verification) and a ReplayGuard keyed on sender+type+message id (recorded after verification, 660s retention, 100k cap) dispatches to dyn FederationStore (PgFederationStore for postgres, SqliteFederationStore for sqlite, FederationMemoryStore for memory backend). Security: SSRF DNS rebinding defense (async hostname resolution rejects private IPs), poison-recovering locks, saturating arithmetic on priority scores, zstd panic elimination, signature verification never bypassed on serialization failure, 2 MiB DefaultBodyLimit on all axum routes, ControlKey Debug redaction. Multi-tenant with sub-collective hierarchy: parent tenants see aggregated routes from child tenants gated by child's `federation_posture` (only Open is visible to the parent; the coordinator refuses `selective` with 400 and treats a stored one as Closed). Store enum dispatch (separate implementations by decision, ADR-0037 — not duplication to remove; every store method goes into all three backends plus backend_parity.rs) (MemoryStore for dev, PgStore for postgres, SqliteStore for sqlite — backend selected via `store_backend` config key or `COORD_STORE_BACKEND` env var, required/explicit). SQLite uses WAL mode, counter table for IP allocation now picks the lowest address no live node holds (advisory lock in PG, BEGIN IMMEDIATE in SQLite) so freed addresses are reused, migrations in `migrations_sqlite/` (shared by coord-store and coord-federation). Federation store follows the same backend selection: SQLite gets SqliteFederationStore (persistent), postgres gets PgFederationStore, memory gets FederationMemoryStore. Session generation counter prevents reconnect races. Configurable default DERP map (JSON file or env `COORD_DERP_MAP`), persisted Noise control key (`COORD_CONTROL_KEY_PATH`; Noise frames capped at 4096 bytes to match Tailscale controlbase), listen addr (`COORD_LISTEN`), sqlite path (`COORD_SQLITE_PATH`, default `coordinator.db`), TOML config file as CLI arg. 210 Rust tests across workspace (94 federation unit, 42 API control_flow, 5 API smoke (real TCP), 21 PgStore integration, 18 PgFederationStore integration, 9 store unit, 3 ACL, 11 noise). Port 8443 is used by tailscale on this machine — do NOT use it
- **Auth**: AT Protocol OAuth via `@atproto/oauth-client-node`, identity scope only (`atproto`); no account tokens are kept
- **Reverse proxy**: Caddy with admin API for dynamic subdomain routing
- **Security model**: Composable role-based permissions, device approval, lockdown
- **ADRs**: `docs/adr/` — design decision records (0001-0038; see docs/adr/INDEX.md)

## Deployment

To deploy to DigitalOcean, follow `deploy/digitalocean/AGENT.md` step by step. It covers DNS, the Cloud Firewall, `.env` (secrets, `OPERATOR_DIDS`, `ATPROTO_PRIVATE_KEY` generated on the Droplet), TLS, first sign-in, and connecting Claude. It works with `doctl` or the DigitalOcean MCP server; Droplet-side steps need SSH. Never print secrets.

## Development

```sh
# Prerequisites: Docker, Node.js 22+
cp .env.example .env
docker compose up -d             # PostgreSQL + Caddy
npm install --include=dev        # NODE_ENV=production is set globally on this box
npx drizzle-kit generate         # Generate migrations
npx drizzle-kit migrate          # Apply migrations
npm run dev                      # http://127.0.0.1:3000 (loads .env via --env-file)
```

```sh

# Add to .env: COORDINATOR_URL=http://localhost:9443  COORDINATOR_API_KEY=dev-coordinator-key-local-only-0000000000

cp .env.coordinator.example .env   # Edit secrets

```

## Key patterns

- **Dashboard client**: React 19 SPA built by esbuild (`esbuild.config.ts`). ESM build with code splitting: entry points `src/client/main.tsx` → `public/js/dashboard.js` and `src/client/join.tsx` → `public/js/join.js`, shared/lazy chunks in `public/js/chunks/`; HTML shells load them with `<script type="module">` (src/routes/dashboard.ts). CSP: `script-src 'self'; style-src 'self'`
- **Tab architecture**: lazy-loaded tabs via `React.lazy` + `Suspense`. Tab registry in `components/registry.ts` gates visibility by permission. `useTenantData` handles load-on-mount (with `error`); `useTenantMutation` handles mutations (single-flight, toast + busy); `toastFailure(e, fallback)` for error toasts
- **Service layer (client)**: typed modules in `services/`, one per API domain; all API paths and request bodies live there. Tabs/components never contain API paths: `useTenantData((tid) => svc.fn(tid), fallback)`, `useTenantParallel({key: (tid) => svc.fn(tid)})` and `mutate((tid) => svc.fn(tid, …), opts)` take service functions. App state is split into `hooks/session.tsx` (session, CSRF, tenant selection, stats), `useTabRoute.tsx` (hash routing + gate fallback) and `useWizard.tsx`; large tabs are split into card components in per-tab folders (`tabs/federation/`, `tabs/boards/`, `tabs/instance/`, `tabs/security/`)
- **Control client abstraction**: `getControlClient(tenant)` from `orchestrator/control-client.ts` — returns either `HeadscaleApiClient` or `CoordinatorApiClient` based on `COORDINATOR_URL` env var. All route handlers and orchestrator modules use this factory, never `new HeadscaleApiClient(...)` directly. Coordinator-only calls use `getCoordinatorClient(tenant?)` from the same module (throws outside coordinator mode; no argument = instance-level client) — never `new CoordinatorApiClient(...)`; branch on `useCoordinator`, not `instanceof`. The `ControlClient` interface matches the Headscale API surface; Headscale user operations (`createUser?`/`listUsers?`/`deleteUser?`) are optional and absent on the coordinator client. Tenant-scoped `CoordinatorApiClient` methods throw on an instance-level client; admin API failures throw `CoordinatorError` (check `isCoordinatorStatus(err, 404)`, never the message). `setAutoApprovers` only pushes: the caller stores `tenants.coordinatorAutoApprovers`
- **Layering**: non-route code (orchestrator, operator, identity, access, members, audit, federation…) never imports from `src/routes/`; shared logic lives in a domain module and routes import it
- **Tenant creation**: `createTenantRecord({ownerUserId, name, parent?, slug?, hostname?})` (`orchestrator/tenant-provisioning.ts`) writes tenant, first address, system roles, default role and originator membership in one transaction (retried on 23505); `provisionTenant` (top-level) and sub-collective creation both use it, then run `provisionTenantInstance` after the commit
- **Coordinator mode** (`COORDINATOR_URL`): when set, tenant provisioning (`orchestrator/tenant-provisioning.ts`) creates tenants via the coordinator REST API (`POST /api/tenants`), stores the coordinator-side UUID in `tenants.coordinatorTenantId`, and skips Docker container lifecycle. Caddy routes all tenant subdomains to the single coordinator. Health monitor skips Docker restarts. Detach/eject call the coordinator first (`CoordinatorApiClient.setParent(null)` → `PUT /api/tenants/{id}/parent`), then the DB; a failed DB write restores the old parent. The children list needs `manage_sub_collectives` and hides suspended children; a child's `maxSubCollectives` follows `checkChildLimit`
- `req.params` values are `string | string[]` in Express 5 — use `param(req, "name")` from `routes/helpers.ts`
- Body validation: `parseBody(schema, req, res, {emptyAsObject?})` (`routes/validation.ts`) sends the one 400 body `{error: "Invalid body", details}`; permission lists use `permissionsSchema` and held permissions come from `effectivePermissions(membership, role, tokenScope?)` (`members/permissions.ts`)
- Device admission: `deviceAdmission(tenant, membership, userId)` (`access/admission.ts`) returns a refusal code (lockdown → device lock (Headscale only) → device limit → approval); routes answer with `sendDeviceRefusal` (`routes/limits.ts`)
- `getTenantForUser(tenantId, userId)` in `routes/helpers.ts` — shared membership+tenant lookup for all protected routes
- `tenantGuard({ param?, originatorOnly?, noAgentToken?, permission? (one or any-of), permissionError?, notLockedDown? })` in `routes/guard.ts` — route middleware (after `requireAuth`/`stepUpForSession`) that runs the lookup and guard clauses with the exact inline bodies (404 "Tenant not found", 403 "Insufficient permissions", 403 "Tenant is in lockdown mode"); handlers read `tenantCtx(res)` → `{tenant, membership, role, userId}`. Use it for new tenant routes; keep checks inline only when they must run in a different order (body validation before lookup, conditional permission/lockdown)
- `hasPermission(membership, role, permission, req)` — originators always pass, others check role's JSONB permissions array; `req` param is required to enforce agent token scope intersection (omitting it would bypass token scoping)
- `Permission` type and `ALL_PERMISSIONS` constant live in `members/permissions.ts`
- Two system roles per tenant: "originator" (all perms) and "citizen" (default for new members, customizable)
- `membership.isOriginator` is the hard source of truth for originator identity (overrides role)
- `isLockedDown(tenant)` — blocks invitations, acceptances, auth key generation, and agent token creation when true
- `toHsUsername(handle)` (`identity/handles.ts`, re-exported by `routes/helpers.ts`) / `tenantLoginServer(slug)` (`routes/helpers.ts`)
- `logAudit(...)` in `audit/log.ts` — fire-and-forget append to `audit_logs` table
- Originator protection: `isOriginator` membership can never be deleted or role-changed (hard 403 in route)
- Tenant provisioning is async (setImmediate) — dashboard polls until status flips from "provisioning" to "running"
- Headscale bootstrap via `docker exec` (API key + initial user), all runtime operations via REST `HeadscaleApiClient`
- Dashboard HTML-escapes all user-controlled data via `esc()` and validates avatar URLs via `safeUrl()`
- Session cookie: `sessionCookieName()` — `__Host-tailnet-session` over HTTPS (host-only, so no subdomain can set or replace it), `sameSite: "lax"`, httpOnly, 7 days. `enforceSessionLifetime` (`auth/session.ts`, mounted after the session middleware) ends sessions 7 days after `createdAt` or 24 h after `lastSeenAt` (written at most every 5 min) — connect-pg-simple's TTL touch alone never expires a busy session; sessions without `createdAt` end
- Routing is case-sensitive: `app.set("case sensitive routing", true)` and every router is `Router({ caseSensitive: true })` (a test scans `src/`); path-prefix middlewares (`csrfProtection` in `auth/middleware.ts`, `enforceDeviceEnrollment`, `enforceAgentScope`) compare lowercased paths. Security headers (incl. HSTS on non-loopback https) come from `security-headers.ts`
- AT Proto handle validation: `HANDLE_RE` regex rejects non-handle input before any HTTP/DNS resolution
- Handle resolution (`identity/handles.ts`: `resolveHandleToDid`, `lookupVerifiedHandle`, `normalizeAccountDid`): DNS TXT → HTTP .well-known → Bluesky public API
- Auth state/session stores are DB-backed (`oauth_states`, `oauth_sessions` tables via Drizzle upsert)
- Express sessions stored in PostgreSQL via `connect-pg-simple`
- Rate limiting (`express-rate-limit`): auth + `.well-known` routes 10 req/min per address; API routes 300 req/min per signed-in user (keyed by user id) and 60 req/min per address for callers without a dashboard session (anonymous, agent tokens). One dashboard page costs about ten requests
- `.well-known/atproto-client-metadata.json` and `.well-known/jwks.json` served for production AT Proto OAuth
- Port allocation retries on unique constraint violation (PG error 23505) up to 3 times
- Port range 10001-10100 allocated from DB; excludes every row's port and reclaims ports held by deleted tenants (deleted rows move to a unique negative placeholder). Coordinator tenants and sub-collectives get negative placeholders — they never consume the Headscale range
- All config flows through Zod-validated `src/config.ts` (including caddyAdminUrl, databaseUrl, atprotoPrivateKey, federationKeyEncryptionKey, tenantPublicPort, headscale.network)
- Instance operators: `OPERATOR_DIDS` (env, comma-separated DIDs; `config.operatorDids`). Only operators — and DIDs an operator designates in `tailnet_creators` — get a tailnet; everyone else signs in to a no-access view (pending invitations + "request to join" the default tailnet via the existing join-request API). Single entry point `canCreateTailnet(user)` in `src/operator/policy.ts`, wrapped with `withTailnetCreationLock` (in-process; the service runs as one app process). `instance_settings` singleton: `singleTailnet` (also refuses sub-collectives, 409 `single_tailnet`), `defaultTailnetId` (first operator tailnet claims it and gets `allowJoinRequests=true`; setting a new default enables join requests). Operator API `/api/operator/*` (`requireOperator`: session or MCP token, never agent tokens): overview, settings, tailnet creators, suspend/unsuspend (`tenants.suspended`, coordinator `PUT /api/tenants/{id}/suspended`; members get 403 `tenant_suspended`; suspended children are hidden from parents), operator delete, user disable/enable (`users.disabled_at`; disable runs the kick cascade `removeMemberCascade` in `members/cascade.ts`). Enforcement middleware `enforceOperatorState` (`src/operator/access.ts`). Public `GET /api/instance`. `POST /api/tenants/mine` creates your tailnet if allowed
- Invitations are the per-tailnet allow-list: invite by handle or DID; invitees see the tailnet's primary public address (`tenantAddress` / `tenant.address`), never `tenants.slug`; responses carry `inviteUrl` (`/invite/:id`, served by the dashboard, sign-in redirect for anonymous visitors). Nothing is sent automatically — admins share the link
- Device approval: devices connect freely by default; when `requireDeviceApproval` is true, auth-key requests create pending `device_approvals` and notify approvers; an approver approves to generate the key. `maxDevices` is enforced at key issuance and approval
- Auth keys: every issued key is tracked in `auth_keys` (both modes). `GET /api/tenants/:id/auth-keys` (manage_devices/originator see all, others own), `DELETE .../auth-keys/:keyId`. Coordinator keys carry `owner` (our user id) and `tags`; the node inherits them, which is how device ownership works in coordinator mode. Kicking a member revokes their keys and deletes their devices in both modes
- Notifications (`src/notifications/`): per-recipient rows (originator + holders of the matching approve_* permission) for device/join/service approval requests and limit hits; `GET .../notifications`, `POST .../notifications/read`. Optional per-tenant webhook (`notificationWebhookUrl` + write-only secret; `X-Atproto-Tailnet-Timestamp` = Unix seconds, `X-Atproto-Tailnet-Signature` = `sha256=` HMAC-SHA256 of `"<timestamp>.<raw body>"` so receivers can refuse old deliveries), https + public addresses only unless `WEBHOOK_ALLOW_PRIVATE=true` (single-org self-hosting), address re-checked at connect time, no redirects, fire-and-forget
- Device locks (Headscale mode only; coordinator mode answers 501 and uses the machine lock): `device_locks` table binds a membership to specific Headscale `machineKey` values — blocks new key generation until unlocked. Creating one needs self or `lock_devices` and step-up; lockdown does not block it (a lock only reduces access)
- Join requests (`routes/join-requests.ts`): `allowJoinRequests` toggle + public `/join/:slug` page; submit body `{message?}` (≤ 500 chars); review gated by `approve_joins` permission; lockdown blocks requests
- Post-login redirect: `req.session.postLoginRedirect` stores destination (validated as local path) through OAuth flow
- Only the owner opens a device (ADR-0036, security rule): open mode applies the ACL policy / allow-all only between devices of members who chose it themselves (`memberships.openAccess`, `PUT .../access-mode/mine`, session only, step-up; sent to the coordinator as `open_owners`, checked with `TenantAccess::is_open_for`) and ownerless devices. Every other device keeps the member view in both modes. Never add a path where an admin, operator, role or policy change exposes another member's devices, and never send a tenant-wide peer delta (each stream gets its own map)
- Device access (ADR-0036): `tenants.accessMode` is `open` (the open policy for members who chose it) or `member` (default for new coordinator tailnets: a device reaches only its owner's devices). Everything else is opened by rules compiled in `access/compiler.ts` (pure) from approved public service posts + their connections and active, unexpired shares, pushed by `syncTenantAccess(tenantId)` (`access/sync.ts`) to the coordinator's `PUT /api/tenants/{id}/access`, which persists them and builds a per-device packet filter and peer list (`member_view` in coord-netmap). Call `syncTenantAccess` after any change to posts, connections, shares or the mode. Coordinator mode only
- Device lock (ADR-0035, `routes/device-trust.ts`, `auth/device-trust.ts`): a user with rows in `trusted_devices` (public keys only) gets a *pending* session after the AT Proto callback (`session.pendingUserId`, no `userId`, so no access) and is sent to `/verify-device`; the browser signs a single-use challenge with a non-extractable WebCrypto P-256 key (`client/lib/device-key.ts`, IndexedDB) and `establishSession` signs it in. Other browsers ask to be trusted (6-character code typed on a trusted device) or use a single-use recovery code (hashes in `recovery_codes`), which sets `session.mustEnrollDevice` and closes the rest of the API (`enforceDeviceEnrollment`). Changing devices, the limit or codes needs a fresh proof (`session.deviceVerifiedAt`, 5 min, `step_up_required`). The first device turns the lock on and ends all other sessions; it needs an AT Protocol sign-in in the last 10 minutes (`session.authAt`, set by `establishSession({atprotoSignIn: true})` in the callback; else 403 `reauth_required`). Sign-ins (success/failure), trusted devices added/removed/approved and recovery codes generated/used are audited as instance-level rows (`tenant_id` NULL; actor required, so a failure for an unknown DID is only logged). Last resort: `node dist/scripts/reset-device-lock.js <handle-or-did>` in the app container. Always create sessions with `establishSession` / `establishPendingSession`, never by setting `req.session.userId` directly
- Device cookie + profile (ADR-0035): a device proof (sign-in and step-up) needs the key signature *and* the device cookie (`__Host-tailnet-device`, HttpOnly, SameSite=Strict; only `trusted_devices.cookie_hash` is stored; a row without a hash never verifies). Coarse browser traits (`deviceProfile`, no versions) are stored at enrolment; a different-looking browser still signs in but sets `profile_warning` and notifies once (`dismiss-warning` needs step-up and resets the profile). The profile never decides access
- Machine lock (ADR-0035 §2, `routes/machine-lock.ts`, coordinator `coord-core/src/lock.rs`): a member locks their own devices in a tailnet to chosen machines via `GET/PUT/DELETE /api/tenants/:id/machine-lock` and `POST .../allow-one` (10 min, admits exactly one new machine). Session only; changes need `requireFreshDeviceProof` when the user has trusted devices. The coordinator persists the lock per (tenant, owner) in `coord_owner_locks`, refuses any other machine key at registration (auth key or approved sign-in alike) and records refused attempts; setting a lock removes the owner's other nodes. `removeMemberCascade` deletes the lock. This is separate from the older `device_locks` table (set by `lock_devices` holders, checked only at key issuance)
- Step-up (`auth/step-up.ts`): a proof (`markDeviceProof`) stores `deviceVerifiedAt` and the hash of the device cookie it saw (`session.deviceCookieHash`); `deviceProofFresh` also needs that same cookie on the request, so a copied session cookie cannot use the 5-minute window. Refusals go through `refuseStepUp` (audited as `step_up_refused`). `stepUpForSession` middleware on sensitive routes (agent token creation, non-GET `/api/operator/*`, hostname changes, share create/accept, device sign-in approval, auth-key creation, device-approval approval, role create/edit/delete/assign and default role, ACL and DERP updates, device-lock creation and removal, tailnet deletion; settings PATCH checks it inline for `SENSITIVE_SETTINGS` (lockdown, agent-token toggles, webhook URL/secret, device approval, join requests), which agent tokens may never change — `src/__tests__/sensitive-routes.test.ts` lists them and checks step-up runs before `tenantGuard`; add new sensitive routes there) and `stepUpMissing` in `/oauth/consent`; applies only to sessions carrying `trustedDeviceId` (token requests pass). The client `api()` wrapper answers `step_up_required` by proving the device and retrying once — do not hand-roll retries in components
- Replicas (ADR-0034, `db/locks.ts`): `withAdvisoryLock` / `LeaderLock` on PostgreSQL advisory locks. `withTailnetCreationLock` is cluster-wide; background loops that must run once per instance (monitor, federation broker) start their tick with `if (!isLeader()) return` from `orchestrator/leader.ts` — do the same for any new loop
- Coordinator replicas (ADR-0034): per-tenant ACL/DERP/auto-approvers/identity persist in `coord_tenant_config` — admin handlers call `state.save_config(tenant, CONFIG_*, &value)` before touching a registry (registries are caches; `load_config` at start, `reload_tenant_config` on remote change). `state.notify_tenant_changed` also publishes to other replicas over PostgreSQL `LISTEN/NOTIFY` (`coord_events`; PgStore `emit`/`publish`, `RemoteEvent`); the nil tenant id means every tenant. Pending sign-ins live in `coord_sign_ins`. `COORD_ROLE=all|control|relay` selects routes; each relay process is one DERP region (`COORD_DERP_REGION_ID` 1-899, heartbeat in `coord_relays`, `refresh_relays`), and peers get each device's reported home relay (`set_home_relay`, `home_region_for`). Run the Rust tests with `TEST_DATABASE_URL` to cover PostgreSQL and the replica tests (`coord-api/tests/replicas.rs`)
- Kubernetes (`deploy/kubernetes/`, Kustomize): `CADDY_ADMIN_URL=off` disables Caddy route sync and `/internal/tls-check` (requires `CONTROL_DOMAIN`); `SKIP_MIGRATIONS=1` leaves drizzle migrations to the `tailnet-migrate` Job
- Local full-stack check without Docker: start a throwaway PostgreSQL (`initdb`/`pg_ctl` on a spare port), `DATABASE_URL=… npx drizzle-kit migrate`, run `coordinator/target/debug/coordinator` (`COORD_STORE_BACKEND=postgres`) and `node dist/index.js` with `CADDY_ADMIN_URL=off CONTROL_DOMAIN=control.localhost SKIP_MIGRATIONS=1`; a session row signed with the local `SESSION_SECRET` stands in for the AT Protocol sign-in
- Gateway + named HTTPS services (ADR-0029/0030, crate `coord-gateway`, `coord-api/src/gateway.rs`): a service post with `web: true` (needs a name and TCP; `httpsServicesAvailable()` from the coordinator's `/health` `gateway` flag) compiles to a DNS record with `port`. The coordinator then registers a gateway node in the tenant (`tag:gateway`, no owner, keys from `derive_key(gateway.key, tenant, purpose)`; node id cached in `GatewayRegistry`, stored as tenant config `gateway`), attaches it to the in-process relay (`DerpServer::attach_local`), and runs WireGuard (`boringtun`) + a per-tenant `smoltcp` stack + TLS/HTTP proxy. `dns_view` resolves ported records to the gateway; `service_rules` adds member-mode rules (viewers → gateway 80/443, gateway → target port); in open mode `gateway_filter` appends gateway → target port to the ACL policy's filter on the service's device; `StoreServices::route` enforces `DnsRecord::visible_to` per request and returns 404 for hidden services exactly as for unknown names. Identity headers `X-Tailnet-User`/`X-Tailnet-Device` are set by the gateway and every caller `x-tailnet-*` header is stripped. Certificate scope (ADR-0038): HTTPS service names are `<name>.<COORD_SERVICE_DOMAIN>` (default `svc.<BASE_DOMAIN>`, label `svc` reserved), never `<name>.<BASE_DOMAIN>`; `Certificate::from_files` refuses a leaf with any SAN outside `*.<service domain>`. Enabled by `COORD_GATEWAY_CERT`/`COORD_GATEWAY_KEY` + `COORD_SERVICE_DOMAIN`. Compose runs it in the `relay` service (`COORD_ROLE=relay`: DERP, STUN, gateway; no admin key, no control key); `coordinator` is `COORD_ROLE=control` and never mounts the certificate. `gateway-certs` copies only Caddy's `*.<SERVICE_DOMAIN>` certificate (`deploy/copy-gateway-cert.sh`, key 0600). The TS service takes the domain from `/health` `service_domain` (`httpsServiceDomain()`). A relay-only process never writes nodes (ADR-0038): `sync_gateway` stores the gateway's public keys in `coord_gateway_offers` (`store.offer_gateway`), a control process registers the node from the offer (`ensure_gateway_node`, refuses keys of any non-gateway node) and reports the tenant change, then the relay starts the gateway. Compose gives the relay the role `tailnet_relay` (`scripts/relay-db-role.sql -v gateway=1`, run at each start by the `relay-db-role` service; URL in `DATABASE_URL_FILE` on the `relay_data` volume) — a new query in relay or gateway code needs a matching grant in that script. Direct paths (ADR-0029 phase 2, off unless `COORD_GATEWAY_UDP_LISTEN` is set; `COORD_GATEWAY_ENDPOINTS` = public `ip:port` list advertised as the node's endpoints through `GatewayOffer.endpoints`): one UDP socket for all tenant gateways (`coord-gateway/src/direct.rs`) routes disco by sender disco key, WireGuard by receiver index, and handshake initiations only from addresses that sent a valid ping; `disco.rs` is the wire format (NaCl box via `crypto_box`); `tunnel.rs` answers pings only for the tenant's devices (UDP pings must carry the node key), sends on the path of the last authenticated packet and falls back to the relay after 15 s. Without it the gateway ignores disco (devices use the relay). `CoordinatorApiClient.listNodes()` hides it from device lists and limits
- Themes: colours are CSS variables in `public/css/dashboard.css` (`paper` default, `parchment`, `forest`, `slate`, `contrast`), chosen per browser via `client/lib/theme.ts` (`<html data-theme>`); never hard-code a colour in a rule
- Device sign-in (ADR-0032): a device registering without a key gets `AuthURL = COORD_DEVICE_AUTH_URL/<id>` (compose: `PUBLIC_URL/device`) and waits on a follow-up register request; pending sign-ins live in the coordinator's memory (`coord-api/src/device_auth.rs`: 128-bit id, 10 min, one per machine, decided once). The dashboard's `/device/:id` page (`routes/device-signin.ts`, `requireSession`) shows hostname/OS/key fingerprint and approves into a tailnet with the same checks as key issuance via `deviceAdmission` (membership, lockdown, device limit; `requireDeviceApproval` tailnets only for the originator; Headscale device locks never apply in coordinator mode), then calls the coordinator's `POST /api/device-auth/{id}/approve`
- Tailnet DNS (ADR-0028): the coordinator stores a per-tenant DNS config (`PUT /api/tenants/{id}/dns`) and sends each device its own view: device names `<device>.<tailnet-address>.<BASE_DOMAIN>` (MagicDNS + search domain), the service records that device may see (`compileDns` in `access/compiler.ts`: private services → the author's devices; approved public services → the author's and connected devices), and a split-DNS route for `BASE_DOMAIN` only when `TAILNET_DNS_UPSTREAM` is set (never an empty route — it would NXDOMAIN the whole domain); the service domain always gets an empty (authoritative) route, because a device only sends names under a routed or MagicDNS domain to its Tailscale resolver. `syncTenantAccess` pushes rules and names together; service names share the namespace of tailnet addresses
- Boards (`routes/boards.ts`): three audiences. Controller board = the originator's public text (`tenants.controllerBoardText`, Markdown subset in `shared/board-text.ts`, linted, rendered by our own code, never HTML/JS; public at `/board/<address>` and on the landing page). Public board = `service_posts` with one device + one port, visible to members only after `approve_services` approval (originator's own posts skip it); members Connect chosen devices of their own (`service_connections`), which opens that one port. Private board = a member's services for their own devices with private names. Changing a public post's device/port drops connections and needs a new approval. Operators control public posts only (`manage_board` removes). A public post can be for some roles (`service_posts.allowed_role_ids`): filter connections with `allowedConnections` (`access/sync.ts`) before compiling rules, names or reach — never read `service_connections` into the compiler without it; role changes call `syncTenantAccess`. `GET .../boards/children` shows a parent the public posts of Open child tailnets (`childBoardVisible`), view only. Public posts need `create_posts`; creating/changing public posts and connecting need `tenants.boardEnabled` (403 `board_disabled`; disconnecting and private posts are unaffected)
- Friends and shares (`routes/sharing.ts`): only accepted friends can share; a share exposes one device of the owner on listed ports/protocols to the guest's devices and is active only after the side that did not start it accepts (an owner who narrows ports sends it back to the guest). Either side ends it. Blocks stop friend requests. No agent tokens, no operator access to share scope. `GET .../my-devices/access` lists who reaches each of the caller's devices and why; it comes from `deviceReach` (`access/reach.ts`), which must agree with `compileAccess` (a test compares them) — change both together
- Agent tokens: `at_`-prefixed Bearer tokens for AI agents; SHA-256 hashed storage; scoped to single tenant + permission subset; mandatory expiry (max 365 days)
- Agent middleware chain: `resolveAgentToken` (Bearer → hash lookup + tenant toggle check → req.agentToken) → `enforceAgentScope` (tenant UUID match + non-tenant route allowlist) → `requireAuth` → route handlers
- Agent token settings: `allowAgentTokens` master toggle, `allowMemberAgentTokens` member toggle; checked at token resolution time (not just creation)
- Agent auth helpers: `authUserId(req)` returns user ID from session or token; `authUserDid(req)` resolves DID (session or DB lookup). All route files use these instead of `req.session.userId` directly
- Agent scope enforcement: `enforceAgentScope` allows `/api/me`, `/api/permissions`, `/api/tenants`, `/health` without tenant UUID; all other non-tenant routes blocked
- Non-member responses: always 404 "Tenant not found" (never 403 — avoids leaking tenant existence)
- Guard clause ordering: param extraction → getTenantForUser → hasPermission → lockdown check → body validation → business logic (`tenantGuard` order: lookup → originatorOnly → noAgentToken → permission → lockdown)
- List queries capped at `.limit(200)` with explicit `.orderBy()`
- Tenant lifecycle (delete/start/stop) audit-logged as `tenant_deleted`/`tenant_started`/`tenant_stopped`
- 17 permissions total: invite, kick, manage_roles, manage_settings, approve_devices, approve_joins, approve_services, lock_devices, view_audit_log, manage_devices, manage_services, manage_board, create_posts, create_agent_tokens, manage_agent_tokens, manage_acl
- ACL management: `GET/PUT /api/tenants/:id/acl` — fetch/push Headscale ACL policy (groups, hosts, tagOwners, autoApprovers); gated by `manage_acl`; Zod-validated before push
- Health monitoring: background 60s interval (`orchestrator/monitor.ts`, `stopHealthMonitor` on shutdown) probes all running tenants via Headscale REST, auto-restarts failed containers, marks "error" if restart fails
- Per-tenant health endpoint: `GET /api/tenants/:id/health` — any member, returns live Headscale probe result
- Structured logging: `pino` via `src/logger.ts`; `LOG_LEVEL` env var (default: info); replaces all console.log/error
- Instance hibernation: `hibernateAfterDays` setting (0 = disabled), `lastActivityAt` updated on API access (debounced 5 min); monitor sweep auto-stops idle tenants past threshold
- `getTenantForUser` touches `lastActivityAt` fire-and-forget when >5 min stale
- Custom DERP relays: `GET/PUT /api/tenants/:id/derp` — per-tenant DERP regions (YAML files hot-reloaded by Headscale), embedded DERP toggle (requires restart), public relay toggle; gated by `manage_acl`; region IDs 900-999. In coordinator mode the DB row stays the source of truth; PUT pushes `{regions, include_default}` to the coordinator's tenant-scoped `PUT /api/tenants/{coordinatorTenantId}/derp` via `CoordinatorApiClient.setDerp`; `embeddedDerpEnabled` is always false in coordinator mode. Never add a global (cross-tenant) DERP write path
- DERP config writes: `updateInstanceConfig()` in `orchestrator/headscale.ts` rewrites config.yaml + derp-custom.yaml; `writeDerpRegionsFile()` generates the YAML paths file
- Per-tenant IP ranges: `GET/PUT /api/tenants/:id/ip-config` — customize IPv4/IPv6 CIDR prefixes and allocation strategy (sequential/random); gated by `manage_settings`; changes trigger container restart
- Exit nodes / subnet routers: `GET /api/tenants/:id/routes` returns `{ exitNodes, subnets }` in both modes; `POST .../routes/:routeId/enable|disable`, `DELETE .../routes/:routeId` (withdraws approval); gated by `manage_devices`. Coordinator: advertised routes come from Hostinfo.RoutableIPs, approval via `POST /api/tenants/{id}/nodes/{node_id}/routes`, tag-based auto-approvers via `PUT /api/tenants/{id}/auto-approvers` (in-memory; TS stores them in `tenants` and the monitor replays them on coordinator `boot_id` change)
- Headscale API is pinned to 0.29.x semantics (`orchestrator/headscale-api.ts`): users are addressed by numeric id (the client resolves names via `getUserByName`), routes are fields on a node (`availableRoutes`/`approvedRoutes`) changed through `POST /node/:id/approve_routes`, so route ids are synthesized by `routeId(nodeId, prefix)` and "delete" withdraws approval; node `expiry`/`lastSeen`/`user` can be null. Check a running instance's `/swagger/v1/openapiv2.json` before adding calls
- Usage + limits: `GET /api/tenants/:id/usage` returns `{current, limits, overLimit, history}` (7-day snapshots, every 5 min); `PUT /api/tenants/:id/limits` sets `maxDevices`/`maxMembers` (0 = unlimited) — originator only, never via agent token; sub-collectives can't exceed the parent. There are no plans (`plan_name` column is unused). Caps are enforced: devices at key issuance/approval, members at invitation accept/join approval (403 `code: device_limit|member_limit`)
- Federation posture: `closed` (default) or `open`; `PUT .../federation/posture` answers 400 "selective posture is not implemented" for `selective` (the enum value stays only for old rows)
- Federation: `GET/POST /api/tenants/:id/federation` for links; `POST .../federation/:linkId/accept|reject|revoke` (accept is blocked by lockdown); `federation_links` table with bidirectional CIDR sharing; gated by `manage_settings`; both sides can revoke active links. A local target that is missing, deleted, suspended, closed or locked down gets one 404 body. Own-instance exemption (plain fetch, http allowed) only for the exact origin of `PUBLIC_URL` (`isOwnOrigin` in `federation/discovery.ts`); broker URLs with a query or fragment are refused; everything else goes through `guardedRequest`. Production with `FEDERATION_ENABLED=true` refuses to start without `FEDERATION_KEY_ENCRYPTION_KEY`; decryption requires a 16-byte GCM tag
- Collective signing keys: one implementation in `src/identity/keys.ts` (`signDetached`/`verifyDetached` detached-JWS EdDSA, `encryptPrivateKey`/`loadPrivateKey`); DB-backed access via `loadCollectiveKeyPair(tenantId)` / `signAsCollective(tenantId, payload)` in `orchestrator/federation-broker.ts` — never decode `collective_dids.encryptedPrivateKey` by hand
- Collective DIDs: `did:web:<host>:collective:<slug>` (port percent-encoded), document served at `/collective/:slug/did.json`; `getResolver()` (`identity/resolver.ts`) answers local collectives from the DB and refuses did:web hosts that resolve to non-public addresses
- Federation broker: two `broker_sessions` per active link (one per side, unique on link + `localTenantId`); accepting side initiates HELLO→CHALLENGE→COMMIT→ESTABLISHED over `POST /api/federation/messages/{hello,commit}`; reconcile loop (30s) retries `connecting` sessions, sends signed keepalives, tears down sessions of inactive links
- CFP message auth (`federation/auth.ts`): recipient collective named by `CFP-Recipient` header; signatures are detached EdDSA JWS over RFC 8785 JCS of the message minus `signature` (`federation/jcs.ts`; Rust `coord-federation` canonical.rs/signing.rs use the same bytes — shared vectors in `coordinator/crates/coord-federation/tests/fixtures/cfp_vectors.json`); verify against `req.body` as received so unknown fields stay covered; HELLO requires an active link with the sender; keepalive/revoke must be signed by the session's peer
- Federated routes: only prefixes inside CIDRs agreed on the link are imported (`filterImportedPrefixes`); Headscale mode installs them as `autoApprovers.routes` for `tag:federation-relay`, coordinator mode via coordinator auto-approvers. Cross-instance LINK_* messages go through a per-link outbox (`federation/outbox.ts`) with backoff; permanent revokes are never retried. The TS service is the authoritative CFP endpoint; the Rust CFP endpoints/broker only run with `COORD_FEDERATION_ENABLED=true`. The whole federation feature is off unless `FEDERATION_ENABLED=true` (src/config.ts): federation/traversal API paths return 404, the broker doesn't start, and the Federation/Traversal tabs are hidden via `features.federation` from `/api/me` (registry `feature` field + `tabEnabled`). Collective DID docs stay served for credentials. Federation is **deferred, not abandoned** (ADR-0033 "Status: deferred"): the unused federation modules it lists (TS `federation/session.ts`, `route-engine.ts`, `scoping.ts`; Rust `coord-federation` `session.rs`, `scoping.rs`, `transport.rs`, `route_engine.rs`) are scaffolding — never delete them as dead code
- Credential revocation: `POST /api/tenants/:id/credentials/:credentialId/revoke` requires the credential `jwt` and only revokes credentials signed by that tenant's collective key
- Sign-in is identification only: the AT Proto OAuth scope is `OAUTH_SCOPE = "atproto"` (never add `transition:*`), the session is revoked (`session.signOut()`) in the callback as soon as the DID is known, and the service keeps no account tokens (`purgeStoredOAuthSessions()` clears older ones at startup). Handle/display name/avatar come from public sources (`identity/account.ts`: PLC directory + Bluesky public API, handle verified both ways)
- Service-auth holder binding: AT Proto accounts prove identity via a `getServiceAuth` JWT (ES256K/ES256, `#atproto` key) minted by the holder's own client; verifier in `credentials/service-auth.ts` checks aud/lxm/exp/jti/signature via `@atproto/crypto.verifySignature`; JTI replay cache in `service_auth_jti_cache` table, swept by monitor. The service cannot mint these tokens for users (it holds no account access)
- Typed resolver keys: `resolveTyped(did, opts)` on `DIDResolver` returns `{key, algorithm, methodId, didKey?}` with `publicKeyMultibase` multikey decoding (secp256k1/P-256 via `@atproto/crypto`); callers filter by methodId and algorithms
- Tenant URLs: `tenantPublicUrl(slug)` in `config.ts` is the single source for the login server and Headscale `server_url` (`<proto>://<slug>.<BASE_DOMAIN>[:TENANT_PUBLIC_PORT]`)
- Caddy routing (`orchestrator/caddy.ts`): the service owns one route, `@id: tailnet_tenants`, kept first in the Caddy server named `tailnet_proxy` (named in the Caddyfile via `servers { name tailnet_proxy }`); `syncTenantRoutes()` rewrites it whole from the DB (all non-deleted tenants with a container) — call it after anything that adds/removes a tenant instance; the monitor also calls it every sweep because Caddy forgets admin-API changes on restart. Never add or remove individual routes
- Caddy admin API calls use `node:http`, not `fetch` — Caddy ≥ 2.11 rejects requests carrying `Sec-Fetch-Mode` (403)
- Caddy admin API (coordinator compose) listens on `10.250.250.2:2019` on the private `caddy_admin` network; only the app (pinned at `.3`) joins it. Tenant vhosts expose only `/key` and `/ts2021`
- Auth hardening: `/auth/login` refuses cross-site `Sec-Fetch-Site`, stores per-browser nonces (`session.oauthLoginNonces`) passed as OAuth `state`, and the callback must match one. An unresolved `Authorization: Bearer` is a 401 (never falls back to the session cookie). Members without `manage_devices` get single-use keys ≤ 24h; enabling lockdown revokes outstanding keys. Default-role changes and role deletion are checked with `missingPermissions` (no escalation via the default role). Hierarchy: nobody may delete or change the permissions of a role, demote (role assign) or kick a member whose role holds permissions they lack (`permissionsAbove` + `rolePermissions` in `routes/helpers.ts`; originators always pass). Agent tokens cannot mint agent tokens. OAuth lookups (did:web, PDS/auth-server metadata, token calls) use `createOAuthFetch` (`auth/atproto.ts`: `safeFetchWrap` from `@atproto-labs/fetch-node` + IP-literal check with `isPublicAddress` + redirects never followed; loopback deployments may reach local servers); `/auth/login` accepts only single-string `handle`/`redirect`
- Built-in DERP relay + STUN (`coordinator/crates/coord-derp`, ADR-0027): the coordinator serves `GET /derp` (Upgrade: DERP), `/derp/probe`, `/derp/latency-check`, `/generate_204` and STUN on UDP 3478. `COORD_DERP_HOSTNAME` (compose: `DERP_DOMAIN`) makes it default DERP region 1; `COORD_STUN_LISTEN` (`off` disables); relay key at `COORD_DERP_KEY_PATH` (default `derp.key` next to the control key). Only registered nodes of non-suspended tenants are admitted (`StoreAdmission`, re-checked every keep-alive) and packets relay only within a tenant or between parent and child. The default DERP map never contains Tailscale's relays; with nothing configured it is empty. No mesh frames, no WebSocket transport
- Tenant containers join the Docker network `HEADSCALE_NETWORK` (shared with Caddy), and Caddy dials `headscale-<slug>:8080`; without it Caddy dials `localhost:<port>` and must run on the host. `ensureOnTenantNetwork()` attaches older containers at startup
- Tailnet addresses (`orchestrator/hostnames.ts`, `tenant_hostnames`): `tenants.slug` is a permanent opaque internal id (`t-` + 10 random chars for new tailnets; never derived from the handle) used only by the coordinator (`X-Tenant-Slug`, set by Caddy), Headscale container names and collective DIDs — never routed or returned publicly. Public names live in `tenant_hostnames`: one live primary (login server for new devices, join/board links) plus aliases (still routed so enrolled devices keep working); retired names stop routing and stay reserved 30 days. New tailnets get a random friendly name (`quiet-harbor-4821`) the originator is asked to change in the setup wizard; Status tab "Tailnet address" card. Originator-only, never agent tokens: `GET/PUT/DELETE /api/tenants/:id/hostnames[/primary|/:name]`; max 5 live names; reserved names blocked. Shared control URL: with `CONTROL_DOMAIN` set (coordinator mode) every tailnet's login server is `sharedControlUrl()` (`https://<CONTROL_DOMAIN>`, a static Caddyfile site exposing only `/key` + `/ts2021`; config refuses a host under `BASE_DOMAIN`) — use `tenantLoginServerFor(tenant)`, never build login URLs by hand. Caddy routes every live name (legacy per-tailnet control hostnames); `/internal/tls-check`, `/join/:name`, `/board/:name` resolve live public names only. Keep a DNS-01 wildcard TLS strategy in production — per-host (on-demand) certificates publish every tailnet name in Certificate Transparency logs
- `package-lock.json` must be accepted by npm 10 (the `node:22-alpine` image runs `npm ci`): a lock written by npm 11 fails there with "Missing: … from lock file". After changing dependencies run `npx npm@10 install --package-lock-only --include=dev --ignore-scripts` and check `npx npm@10 ci --dry-run --omit=dev --ignore-scripts`
- Schema changes need a migration in `drizzle/` (hand-written SQL is fine: next free number plus a `_journal.json` entry) — commit it with the schema change
